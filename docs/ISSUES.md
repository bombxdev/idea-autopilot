## ISSUE-012 · 2026-10-30 · แก้แล้ว (v0.3.0) — สกิลจากอินเทอร์เน็ตอาจมีคำสั่งอันตรายหรือหลอก AI
- **อาการ / ความเสี่ยง:** `SKILL.md` เป็นข้อความที่ AI เชื่อฟัง ใครก็เผยแพร่ได้ สกิลร้ายอาจสั่งให้ข้ามกติกา ซ่อนจากเจ้าของ ส่งกุญแจออกไป หรือโหลดโค้ดมารัน บางแหล่งจัดอันดับด้วยยอดติดตั้งซึ่งไม่ได้บอกว่าปลอดภัย
- **สาเหตุ:** ไม่มีด่านตรวจระหว่าง “เจอสกิล” กับ “AI อ่านสกิล”
- **วิธีแก้:** ช็อปดึงเฉพาะข้อความ `SKILL.md` จาก `api.github.com` / `raw.githubusercontent.com` เท่านั้น (ไม่ตาม redirect ไปที่อื่น) ผูกกับ commit และ sha256 ที่ผู้ใช้เปิดดู (ตอนติดตั้งดึงซ้ำและต้องตรงกัน) ผ่านตัวสแกน `skills::scan` ระดับ danger บล็อกถาวร ระดับ warn ต้องติ๊กหลังอ่านเนื้อหาเต็ม AI ติดตั้งเองไม่ได้ ไฟล์ใหญ่เกิน 60 KB ถูกปฏิเสธ ชื่อสกิลซ้ำจากคนละที่มาไม่ทับของเดิม สกิลเป็นเพียงคำแนะนำ ระบุใน `AGENTS.md`/`SKILLS.md` ว่าไม่เหนือกฎของบอท
- **ไฟล์:** `skills.rs` (scan, shop_*), `Skills.svelte`, `workspace.rs`
- **หมายเหตุ:** ตัวสแกนเป็นกฎแบบ heuristic ไม่ใช่เครื่องรับประกัน ด่านจริงคือการอ่านตัวอย่างเต็มก่อนติดตั้ง ทดสอบกับ GitHub จริงแล้ว (สกิลของ Anthropic 8 ตัวแรกผ่านเป็น clean)

## ISSUE-011 · 2026-10-30 · แก้แล้ว (v0.3.0) — สกิลเยอะจนไม่รู้ตัวไหนดี ซ้ำซ้อน และไม่มีใครวัดผล
- **อาการ:** มีสกิลหลายตัวทำเรื่องเดียวกัน ไม่รู้ว่าตัวไหนช่วยจริง การลบตัวซ้ำทิ้งอาจเสียสูตรที่ดีไป
- **สาเหตุ:** สกิลเป็นแค่ไฟล์ ไม่มีข้อมูลว่าถูกใช้และผลเป็นอย่างไร และไม่มีแนวคิดว่าสูตรต่างกันก็ดีได้คนละแบบ
- **วิธีแก้:** ตาราง `skills` / `skill_runs` เก็บสถานะและผลต่อรอบ ตระกูล (family) จัดสูตรที่ทำงานเดียวกันไว้ด้วยกัน บอทเสนอหนึ่งสูตรต่อตระกูลต่อรอบ ลองให้ครบก่อน แล้วเอนไปทางที่ผลดีกว่า ผู้ใช้ปักหมุดได้ ตัวเลขเป็นข้อมูลประกอบ ไม่ตัดสินแทนผู้ใช้
- **ไฟล์:** `skills.rs` (`select`, `pick_variant`, `finish_run`), `db.rs`, `scheduler.rs` (`launch`, `finish`), `prompts.rs` (`skills_used`)
- **หมายเหตุ:** อัตราสำเร็จ = รอบที่สกิลถูกเปิดใช้และงานจบ ok ไม่ได้พิสูจน์ว่าสกิลเป็นเหตุ AI บางตัวพิมพ์ผลน้อยจึงอาจนับต่ำกว่าจริง (ไม่เกินจริง) แนวคิดและแผนต่อยอดอยู่ใน `docs/ROADMAP.md`

## ISSUE-005 · 2026-10-30 · แก้แล้ว — ย้าย/คัดลอกโปรแกรมไปที่ใหม่ แต่ path ยังเป็นของเดิม
- **อาการ:** เปิดโปรแกรมจากโฟลเดอร์ใหม่แล้วยังใช้ข้อมูลและ path ของที่เก่า
- **สาเหตุ:** ตัวเก่าที่ซ่อนอยู่ที่ tray ยังรันอยู่ ตัวที่เปิดใหม่ถูกตัวกันเปิดซ้อน (single instance) ส่งกลับไปที่ตัวเก่าแล้วปิดตัวเอง ทำให้ไม่เคยลงทะเบียนเปิดพร้อม Windows ใหม่ และใช้ข้อมูลเดิมต่อ
- **วิธีแก้:** ตัวที่รันอยู่ตรวจว่าตัวใหม่มาจากไฟล์คนละที่ แล้วขึ้นแถบเตือนบอกที่อยู่ข้อมูลของทั้งสองตัว ปุ่ม “ปิดตัวนี้ แล้วใช้ตัวใหม่” จะเปิดตัวใหม่ (`--wait-old`) แล้วปิดตัวเก่า เมื่อโฟลเดอร์ย้ายจริง ระบบบันทึกเหตุการณ์ “โฟลเดอร์โปรแกรมย้ายจาก … มาที่ …” และปรับสิ่งที่ผูกกับ path (เปิดพร้อม Windows, skill, AGENTS.md ของไอเดีย) ให้ใหม่ พร้อมเตือนโฟลเดอร์ sync/brain/inbox ที่หาไม่เจอแล้ว
- **ไฟล์:** `lib.rs` (`switch_copy`, `root_for_exe`, single-instance), `main.rs`, `App.svelte`
- **วิธีย้ายที่ถูก:** ปิดโปรแกรมจากเมนู tray → ย้ายทั้งโฟลเดอร์ (ต้องมี `data` ติดไปด้วย) → เปิดจากที่ใหม่

## ISSUE-004 · 2026-10-30 · แก้แล้ว — กด Enter พลาดตอนพิมพ์ไอเดีย / แก้ prompt ไม่ได้ / ชื่อโฟลเดอร์เพี้ยน
- **อาการ:** พิมพ์ยังไม่จบแต่อยากขึ้นบรรทัดใหม่แล้วกด Enter ไอเดียถูกส่งไปทั้งที่ยังไม่เสร็จ และแก้ไม่ได้ ชื่อโฟลเดอร์ภาษาอังกฤษที่ AI ตั้งก็ตามข้อความที่ผิดไปด้วย
- **สาเหตุ:** ช่องจดไอเดียด้านบนเป็นบรรทัดเดียวที่ Enter = ส่ง บอทเริ่มทำทันที และไม่มีทางแก้ข้อความหลังส่ง
- **วิธีแก้:** (1) ช่องเป็นหลายบรรทัด Shift+Enter ขึ้นบรรทัดใหม่ และเลือกโหมดกันพลาดได้ (ตั้งค่า → ส่งไอเดียด้วยปุ่ม: Ctrl+Enter ส่ง, Enter ขึ้นบรรทัดใหม่) ใช้กับหน้าต่าง Ctrl+Shift+Space ด้วย (2) บอทรอ 90 วินาทีก่อนเริ่มไอเดียที่เพิ่งจด (ปรับได้) (3) ปุ่ม “✏️ แก้ข้อความ” ในหน้าไอเดีย: ถ้า AI ยังไม่ลงลึก ระบบเริ่มตีความใหม่ ล้างแผน และตั้งชื่อโฟลเดอร์ใหม่ตามข้อความใหม่ ถ้าลงลึกแล้วจะแก้ `IDEA.md` และสั่งให้ AI อ่านข้อความใหม่
- **ไฟล์:** `QuickAdd.svelte`, `Capture.svelte`, `IdeaDrawer.svelte`, `scheduler.rs` (`edit_idea`, `next_idea`), `workspace.rs` (`rewrite_idea_md`)

- **อาการ:** Codex/Gemini/OpenCode ใช้โมเดลเดียวกันทุกขั้น งานเล็กก็ใช้โมเดลแพง และไม่ปรับ effort
- **สาเหตุ:** ระดับโมเดลของ AI อื่นเป็นค่าว่าง (ใช้ค่าเริ่มต้นของโปรแกรมนั้น) และ effort ส่งให้เฉพาะ Claude
- **วิธีแก้:** อ่านรายชื่อโมเดลที่ AI นั้นมีเอง (Codex: `models_cache.json`, OpenCode: `opencode models`) จัดเป็นเร็ว/กลาง/แรงจากคำอธิบายของโมเดล ส่ง effort ให้ Codex ตามที่โมเดลรองรับ และระบุเองได้ที่ ตั้งค่า → โมเดลและ effort (ชื่อโมเดลจริง + effort) ซึ่งชนะค่า auto เสมอ
- **ไฟล์:** `providers.rs`, `router.rs`, `scheduler.rs`, `Settings.svelte`
- **หมายเหตุ:** Gemini CLI ไม่มีรายชื่อโมเดลให้อ่าน จึงยังใช้โมเดลเดียวจนกว่าจะกรอกชื่อเอง

## ISSUE-001 · 2026-10-30 · แก้แล้ว — เพื่อนติดตั้ง Claude Desktop แล้วแต่แอปบอกว่า “ไม่พบ AI ในเครื่อง”
- **อาการ:** หน้าต้อนรับแสดงทุก AI เป็น “ยังไม่ได้ติดตั้ง” ทั้งที่ใช้ Claude Code ผ่าน Claude Desktop เป็นประจำ
- **สาเหตุ:** แอปหา `claude` เฉพาะใน PATH แต่ Claude Desktop เก็บตัว Claude Code ไว้ที่ `%APPDATA%\Claude\claude-code\<รุ่น>\<hash>\claude.exe` ซึ่งไม่อยู่ใน PATH (ไม่ต้องลง Claude CLI เพิ่ม)

- **ไฟล์:** `providers.rs` (`resolve_known_dirs`), `remote.rs`
- **หมายเหตุ:** ถ้าเพื่อน login ผ่าน Desktop อย่างเดียว อาจอ่านโควต้าจริงไม่ได้ แอปจะใช้งบชั่วโมงแทน กด “ทดสอบสั่งงานจริง” เพื่อเช็ก login
